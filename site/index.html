Exa wrote about how they search the web: send each query to a few clusters, scan compressed codes, then rerank exactly. They shared the idea, not code or numbers. sieve is my own engine built on that idea, written from scratch in Rust, measured end to end, and pushed to a billion vectors on one laptop.

Head-to-head from SSD

Level with Microsoft’s DiskANN, at a fraction of the latency.

DiskANN is Microsoft’s index for data larger than memory, and the standard to beat. Both ran on the same laptop over the same 10M SPACEV vectors and queries, from a cold page cache, in about 0.5 GB of RAM each. Above recall 0.94, sieve answers in under 3 ms. It fetches its candidates from SSD in one parallel batch, while DiskANN waits on a chain of dependent reads.

Where the lines cross

DiskANN at 48 threads leads at low recall, where its graph walk is short. As recall rises its reads stack up one after another, and from 0.955 the two systems are level on throughput while sieve stays 7–10× quicker per query. Against DiskANN on equal threads, sieve is ahead from recall 0.91 up.

How a query runs

Four steps, a few milliseconds.

  1. 01Route

    The query is compared with 131,072 cluster centres, and only the closest clusters are opened.

  2. 02Scan

    Every vector in those clusters is scored from a 1-bit RaBitQ code held in RAM, at about 950 million codes per second per core.

  3. 03Rerank

    The best candidates are read exactly from SSD as int8 rows in one parallel batch, so 100 GB of vectors never has to fit in 24 GB of RAM.

  4. 04Return

    The ten nearest come back. Median 2.7 ms, 99th percentile 11.2 ms.

What it costs

Seconds to build, half a gigabyte to serve.

sieve builds the 10M index in 7 seconds, where DiskANN takes three minutes. The trade-off shows when every vector already fits in RAM: there DiskANN’s graph checks about 1,840 vectors per query against sieve’s 222,000 compressed codes, and it is faster. sieve is built for the case where the data doesn’t fit.

How it was measured

One laptop, public data, every run reproducible.

  • Built independentlyExa’s post described the architecture and published no code or benchmarks. The implementation, the tuning and every number here are sieve’s own.
  • One machineApple M4 Pro, 12 cores, 24 GB of RAM, internal SSD. No servers, no GPU, no cloud.
  • Public benchmarksMS SPACEV-1B (100-d int8) with official ground truth. Also 113.5M MS MARCO passages: recall 0.909 at 4.8 ms median.
  • Cold means coldIndex files are evicted from the OS page cache before every SSD run, checked with mincore.
  • Fair to DiskANNIts disk index had no macOS read path, so a small patch adds uncached pread, matching its Linux path.
  • One recall metricThe head-to-head scores both systems with DiskANN’s strict recall@10. The 1B figures are tie-aware, within 0.001.
